### Step 3. Configuration and its tests (R1; T1 to T3)

`src/config.js` exports `loadConfig(env)`, which returns `{ port }` and touches no global. Only an unset `PORT` (`undefined`) gives the default 3000. A set value must match `/^\d+$/` and be within 1 to 65535, otherwise `loadConfig` throws `new Error("PORT must be an integer from 1 to 65535")`; so `""`, `" 80"`, `"8e3"`, `"0x50"` and `"80.5"` are rejected, as the regular expression is stricter than `Number()`. Write `test/config.test.js`, then run `npm run lint` and `npm test`.

### Step 4. Middleware and error-handler tests (R5 to R8; T4 to T6)

`src/middleware.js` exports `createRequestLogger`, `notFound` and `createErrorHandler`. `notFound(req, res)` answers ``res.status(404).json({ error: `Route ${req.method} ${req.path} does not exist` })`` (API-6).

The logger reads the path when the request arrives: a router mounted later rewrites `req.url` while it runs, and `originalUrl` carries the query string (SEC-10). The monotonic clock keeps the duration non-negative.

```javascript
function createRequestLogger(log) {
  return (req, res, next) => {
    const startedAt = process.hrtime.bigint();
    const path = req.path;
    res.on("finish", () => {
      const durationMs = Math.round(Number(process.hrtime.bigint() - startedAt) / 1e6);
      log(`${new Date().toISOString()} ${req.method} ${path} ${res.statusCode} ${durationMs}ms`);
    });
    next();
  };
}
```

The error handler keeps all four parameters, since Express recognizes it by them. The stack goes to the injected `log`, never into the response; after the headers are sent it delegates to Express.

```javascript
function createErrorHandler(log) {
  return (error, req, res, next) => {
    const hasValidStatus = Number.isInteger(error.status) && error.status >= 400 && error.status <= 599;
    const status = hasValidStatus ? error.status : 500;
    if (status >= 500) {
      log(error.stack ?? String(error));
    }
    if (res.headersSent) {
      return next(error);
    }
    res.status(status).json({ error: status >= 500 ? "Internal server error" : error.message });
  };
}
```

`test/error-handler.test.js` mounts the handler on its own `express()` app, because `createApp` has no throwing route. `/throws` (sync) and `/rejects` (async) raise `new Error("secret detail")`; `/bad-input` and `/bad-status` call `next` with `Object.assign(new Error("Bad input"), { status: 400 })` and the same with `status: 200`. `log` pushes into an array that `beforeEach` empties. T4 runs once for `/throws` and once for `/rejects`; each run expects exactly one log entry that holds the message and a stack frame (`\n    at `).

### Step 6. Entry point (R3)

`src/server.js` calls `loadConfig(process.env)` in a `try`/`catch`, inside a `main()` function. On an error it prints `Invalid configuration: <message>` with `console.error`, sets `process.exitCode = 1` and returns without listening. Failures set `process.exitCode` instead of calling `process.exit()`: the message is written first, and the process then ends by itself, as nothing else is running. Otherwise it listens:

```javascript
// Express 5 passes startup errors such as EADDRINUSE to the callback instead of throwing.
createApp({ ...config, log: console.log }).listen(config.port, (error) => {
  if (error) {
    console.error(`Cannot listen on port ${config.port}: ${error.message}`);
    process.exitCode = 1;
    return;
  }
  console.log(`Task API listening on port ${config.port}`);
});
```

## Risks

- ESLint config format: the plan uses the documented ESLint 10 `defineConfig` form; if `npm run lint` rejects it, adjust the format and keep the R11 rules.
- Error stacks share `log` with the request lines, so the server writes them to stdout; a separate error channel belongs to the structured-logging follow-up (out of scope).
- A 4xx error with an empty message would give an empty `error` text. Today only the JSON parser produces 4xx errors, and its messages are never empty; later increments that throw their own 4xx errors must set a message (API-4).
- Log tests assert right after the response; if one ever proves flaky, wait for the line instead.
